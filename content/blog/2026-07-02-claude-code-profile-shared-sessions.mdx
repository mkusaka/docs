## まとめ

- Claude Codeは`CLAUDE_CONFIG_DIR`で設定ディレクトリを切り替えられる
- `CLAUDE_PROFILE`は標準ではないので、シェル関数で`CLAUDE_PROFILE` → `CLAUDE_CONFIG_DIR`に変換する
- `~/.claude.json`はOAuth sessionなどを含むので共有しない
- `settings.json`、`skills`、`commands`、`projects`、`sessions`あたりをsymlinkすると、認証は分けつつ設定・拡張・履歴はだいたい共有できる

## CLAUDE_PROFILEを作る

`~/.zshrc`などに追加する：

```zsh
claude() {
  local dir

  case "${CLAUDE_PROFILE:-default}" in
    default|work) dir="$HOME/.claude" ;;
    personal) dir="$HOME/.claude-personal" ;;
    *)
      echo "unknown CLAUDE_PROFILE: ${CLAUDE_PROFILE}" >&2
      echo "expected: default, work, or personal" >&2
      return 2
      ;;
  esac

  CLAUDE_CONFIG_DIR="$dir" command claude "$@"
}
```

```bash
claude
CLAUDE_PROFILE=personal claude
CLAUDE_PROFILE=personal claude auth login
```

## 設定とセッションを共有する

`~/.claude-personal`を作り、ユーザー設定、skillやcommand、セッション履歴を`~/.claude`へsymlinkする。

```bash
profile="$HOME/.claude-personal"
shared="$HOME/.claude"

mkdir -p "$profile"

for item in \
  settings.json \
  skills commands \
  projects sessions transcripts todos tasks plans file-history history.jsonl
do
  [ -e "$shared/$item" ] || continue
  [ -e "$profile/$item" ] || [ -L "$profile/$item" ] || ln -s "$shared/$item" "$profile/$item"
done
```

`hooks`のようにスクリプト実体を置くディレクトリは、`settings.json`側で絶対パス参照していればsymlinkしなくても動く。`plugins`はprofileごとに実体を持つ。

## 注意点

- `~/.claude.json`や`credentials`、`token`、`oauth`、`auth`っぽいファイルは共有しない
- `--continue`やtrust設定など、`.claude.json`側のstateに寄るものはprofileごとに分かれることがある
- Claude Code公式の想定は`CLAUDE_CONFIG_DIR`単位の分離なので、この構成はsymlink運用
